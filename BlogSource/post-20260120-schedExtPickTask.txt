# Analyzing sched_ext Pick Task Logic in Linux Kernel

Date: 20/1/2026
Author: Chunbo

## Introduction

## Key Function -- start from pick_task_scx in 6.17.9

Init: In the initialization part, note that the "keep_prev" is related to SCX_RQ_BAL_KEEP.

```c
static struct task_struct *pick_task_scx(struct rq *rq)
{
	struct task_struct *prev = rq->curr;
	struct task_struct *p;
	bool keep_prev = rq->scx.flags & SCX_RQ_BAL_KEEP;
	bool kick_idle = false;
```
Then we comes to WORKAROUND path.
As the comment said, the "fair" may go through balance() without balance_scx(),
and call pick_task_scx(). Thus, we need a workaround method:
1. When SCX_RQ_BAL_PENDING is set, representing that a balance is not processed,
we keep the previous task if it's queued. Otherwise, we kick_idle, so that
the CPU could join the scheduling process later, 
by calling scx_kick_cpu(rcu_dereference_sched(scx_root), cpu_of(rq), SCX_KICK_IDLE) 
in the following part.

2. When keep_prev is true, however the previous guy is not SCX task,
set keep_prev to false in case it is treated as a SCX task.

```c
	/*
	 * WORKAROUND:
	 *
	 * %SCX_RQ_BAL_KEEP should be set iff $prev is on SCX as it must just
	 * have gone through balance_scx(). Unfortunately, there currently is a
	 * bug where fair could say yes on balance() but no on pick_task(),
	 * which then ends up calling pick_task_scx() without preceding
	 * balance_scx().
	 *
	 * Keep running @prev if possible and avoid stalling from entering idle
	 * without balancing.
	 *
	 * Once fair is fixed, remove the workaround and trigger WARN_ON_ONCE()
	 * if pick_task_scx() is called without preceding balance_scx().
	 */
	if (unlikely(rq->scx.flags & SCX_RQ_BAL_PENDING)) {
		if (prev->scx.flags & SCX_TASK_QUEUED) {
			keep_prev = true;
		} else {
			keep_prev = false;
			kick_idle = true;
		}
	} else if (unlikely(keep_prev &&
			    prev->sched_class != &ext_sched_class)) {
		/*
		 * Can happen while enabling as SCX_RQ_BAL_PENDING assertion is
		 * conditional on scx_enabled() and may have been skipped.
		 */
		WARN_ON_ONCE(scx_enable_state() == SCX_ENABLED);
		keep_prev = false;
	}
```

The following part is the core logic of picking task:
1. If the balancing process decides to keep the previous task,
refill the slice of the previous task.
2. If not, we get the new task from the rq. Most likely, we got the task we want,
but if we can not get the task, the CPU becomes idle, 
or if this task does not have time slice, refill it.
```c
	/*
	 * If balance_scx() is telling us to keep running @prev, replenish slice
	 * if necessary and keep running @prev. Otherwise, pop the first one
	 * from the local DSQ.
	 */
	if (keep_prev) {
		p = prev;
		if (!p->scx.slice)
			refill_task_slice_dfl(rcu_dereference_sched(scx_root), p);
	} else {
		p = first_local_task(rq);
		if (!p) {
			if (kick_idle)
				scx_kick_cpu(rcu_dereference_sched(scx_root),
					     cpu_of(rq), SCX_KICK_IDLE);
			return NULL;
		}

		if (unlikely(!p->scx.slice)) {
			struct scx_sched *sch = rcu_dereference_sched(scx_root);

			if (!scx_rq_bypassing(rq) && !sch->warned_zero_slice) {
				printk_deferred(KERN_WARNING "sched_ext: %s[%d] has zero slice in %s()\n",
						p->comm, p->pid, __func__);
				sch->warned_zero_slice = true;
			}
			refill_task_slice_dfl(sch, p);
		}
	}

	return p;
}
```
