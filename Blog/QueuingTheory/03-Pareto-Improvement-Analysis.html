Queueing Theory 2026-04-12

Pareto Improvement: Priority vs CPUMask

Corrected analysis: gain decomposition and fair comparison.

Pareto Concepts

Pareto Improvement

From S1 to S2: at least one party gets better, none get worse

Pareto Dominance

S2 is no worse than S1 in all dimensions, and strictly better in at least one

Pareto Optimal

No other state can Pareto-improve it. All Pareto-optimal points form the Pareto frontier.

Critical Correction: Asymmetric Comparison

Original Error

Comparing Wq_A^pri (using N cores) with Wq_A^iso (using k cores) is unfair — different resource pools.

Corrected Analysis

When compared with same c_A = k, priority does NOT improve A's delay. The improvement for B comes from architecture change (pool merging).

Two Comparison Scenarios

Scenario 1: Same Resource Pool (Fair)

CPUMask: c_A = k, c_B = N-k
Priority:  c_A = k, c_B = N-k (A can preempt B)

Result:
  Wq_A^pri = Wq_A^iso (A's delay same!)
  Wq_B^pri < Wq_B^iso (B's capacity larger)
  → Pareto improvement for B, A unchanged

Scenario 2: Different Pool (Original)

CPUMask: c_A = k cores
Priority:  c_A = N cores (full pool)

Result:
  A's delay improves (N > k)
  But this is ARCHITECTURE gain, not scheduling gain

Corrected Proof (Same Resource Pool)

Theorem: With same c_A = k, Priority Pareto-improves CPUMask
         because B's capacity increases while A's delay is unchanged.

Proof:

For A (same resource pool):
  Wq_A^iso = ErlangC(k, λ_A/μ) / (kμ - λ_A)
  Wq_A^pri = ErlangC(k, λ_A/μ) / (kμ - λ_A)

  → Wq_A^pri = Wq_A^iso  (A is unchanged) ✓

For B:
  CPUMask: C_B^iso = (N-k)μ
  Priority: C_B^pri = (N-k)μ + (kμ - λ_A) = Nμ - λ_A

  Since kμ > λ_A (stability condition):
  C_B^pri > C_B^iso  ✓
  → Wq_B^pri < Wq_B^iso

Conclusion: Wq_A^pri = Wq_A^iso AND Wq_B^pri < Wq_B^iso
           Priority is Pareto improvement (A unchanged, B better) ■

Source of Pareto Improvement

Key Inequality: kμ > λ_A

CPUMask gives A more cores than A actually needs

Waste = kμ - λ_A (idle capacity on A's dedicated cores)

CPUMask: A's idle cores are wasted (B cannot access)
Priority: B reclaims A's idle cores (A doesn't use them)

Pareto improvement source = eliminating kμ - λ_A waste

NOT "stolen from A" but "reclaimed from idle"
A loses nothing, B gains capacity for free.

Why This is Counter-intuitive

The conservation law seems to say "impossible" within a single queue:

Conservation Law (single queue):
  Σ ρ_k × Wq_k = ρ² / (μ(1-ρ)) = constant

This says: A waits shorter → B waits longer
Zero-sum game, no Pareto improvement possible.

BUT: Pareto improvement happens ACROSS architectures,
not within the same queue. The "system" changes
from two isolated queues to one shared queue.

Factors Outside the Model

Cache Interference (δ)

Shared cores: A and B alternate → L1/L2 cache thrashing → A's effective service rate decreases by δ

When δ > δ*: True tradeoff exists (neither dominates)

Scheduler Latency

Real preemption has μs-level delay; extreme cases may delay A's response

Non-preemptible Sections

Kernel code sections (spin locks, interrupt handling) where B can block A

NUMA Effects

Cross-NUMA memory access has higher latency; CPUMask can bind A to specific NUMA node

Corrected Conclusions

  • 1. Gain Decomposition: Priority's advantage comes from architecture change (pool merging), not scheduling superiority
  • 2. Fair Comparison: With same c_A = k, A's delay is identical in both strategies — priority doesn't help A's latency
  • 3. Pareto Improvement: Exists for B (capacity gain) while A remains unchanged — positive-sum, not zero-sum
  • 4. Outside Model: Cache interference (δ), scheduler latency, non-preemptible sections can invalidate the theoretical advantage
  • 5. Best Practice: k=1 (safety net) + Priority. Default to priority, measure δ, only add CPUMask when δ makes Wq_A unacceptable
